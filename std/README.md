# Solcore standard library snapshot

The `.sol` files in this directory come from the Haskell reference standard
library at revision
`a7b7afb0638e50895008d778a167afd0e50a2c86`:

```text
https://github.com/argotorg/solcore/tree/a7b7afb0638e50895008d778a167afd0e50a2c86/std
```

Upstream now uses canonical `.sol` syntax, so no syntax migration is required.
Local whitespace-only formatting is applied with `solcore-fmt`; source tokens,
literals, and comments are retained.
The copies under
`crates/parser/tests/fixtures/corpus/ok/std/` are parser fixtures and must remain
byte-for-byte identical to the files here.

This README is Rust-repository metadata; it is not part of the upstream std
snapshot.

## Synchronization policy

Keep the vendored sources aligned with the recorded upstream revision, allowing
local whitespace-only formatting with `solcore-fmt`. When upstream changes,
update and format the vendored files and their parser-corpus copies together.

Do not reproduce an upstream compiler bug or problematic specification merely
for compatibility. Record confirmed upstream problems in the local `issues.md`
without staging that file, and document intentional Rust behavior in
[`SEMANTIC_DIFFERENCES.md`](../SEMANTIC_DIFFERENCES.md). Any necessary library
exception must be documented explicitly instead of silently changing the
recorded snapshot.

## Local exceptions

- `std.sol`, `ABIEncode<ABITuple<tuple>>`: a dynamic tuple stores its tail
  offset at `basePtr + offset` instead of `basePtr`. Upstream overwrites the
  first word of the enclosing region (a preceding field, or a dynamic sum's
  tag) whenever the tuple is not at head offset 0. Regression:
  `tests/e2e/abi-tuple-offset`.
- `signed.sol`, `unsigned.sol`, and the checked-arithmetic section of `std.sol`
  (`panic`, `uAddChecked` .. `sModChecked`, and the `uint256`
  `Add`/`Sub`/`Mul`/`Div`/`Mod` instances) are ported ahead of upstream from
  the Haskell `signed-intergers-std` branch. `std.signed` provides `int8` ..
  `int256` and `std.unsigned` provides `uint8` .. `uint128`; they are accepted
  as external ABI types (`intN`/`uintN`). Arithmetic on them and on `uint256`
  is checked as in Solidity 0.8: overflow, underflow and `MIN / -1` revert with
  `Panic(0x11)`, division or modulo by zero with `Panic(0x12)`.
  One local difference from that branch: the conditions inside the
  `*Checked` helpers are bound to `let` locals instead of nested calls. This
  keeps call nesting within the default parser stack; behavior is identical.
  Regressions: `tests/e2e/int-ops` (ABI decode/encode and storage),
  `tests/e2e/checked-arith` (upstream vectors), and
  `tests/e2e/{signed,unsigned}-integers-{narrow,wide}` (every arithmetic,
  bitwise, comparison and bounds operation per width, generated by
  `scripts/gen-int-fixtures.py`).
- `unchecked/unsigned.sol` and `unchecked/signed.sol` are local, with no
  upstream counterpart. They declare the `UncheckedAdd`/`UncheckedSub`/
  `UncheckedMul`/`UncheckedDiv`/`UncheckedMod` traits (in `unsigned.sol`,
  re-exported by `signed.sol`) and their wrapping instances for `word`,
  `uint8` .. `uint256` and `int8` .. `int256`. The compiler desugars `+ - * / %`
  (and the compound assignments) written inside `unchecked { ... }` to these
  traits, so such a block must import one of the two modules. Results wrap to
  the type's width; `MIN / -1` is `MIN`; division or modulo by zero still
  reverts with `Panic(0x12)`. Regressions: `tests/e2e/unchecked-scope`
  (lexical scope) and `tests/e2e/unchecked-{signed,unsigned}-integers`
  (generated by `scripts/gen-int-fixtures.py`).

## Compatibility decisions

The canonical analysis of Haskell/Rust semantic differences, ABI evidence
gaps, and compatibility decisions is in
[`SEMANTIC_DIFFERENCES.md`](../SEMANTIC_DIFFERENCES.md). ABI metadata support
alone does not make a type externally dispatchable. Keep ABI JSON, selector
spelling, calldata decoding, and result encoding aligned.

## Verification

After every std update, verify at least:

```sh
for file in ABIGeneric.sol Generic.sol StorageGeneric.sol dispatch.sol \
  eip712.sol eip7951.sol opcodes.sol signed.sol std.sol unsigned.sol \
  unchecked/signed.sol unchecked/unsigned.sol; do
  cmp "std/$file" "crates/parser/tests/fixtures/corpus/ok/std/$file" || exit 1
done
cargo test -p solcore-parser -p solcore-hir-ty -p solcore-specialize --locked
E2E=1 E2E_REQUIRED=1 cargo test --profile e2e \
  -p solcore-yul --test e2e --locked -- \
  --nocapture --test-threads=1
```

Imported upstream raw-vector cases retain their calldata, output, and EVM
metadata; fixtures may append local regressions. Both Yul and Sonatina compile
and execute the complete set against Osaka. See
[`tests/e2e/README.md`](../tests/e2e/README.md) for the full validation
commands.
